# 6. Надёжность

## 6.1 Цели восстановления

| Компонент | RTO | RPO |
|---|---|---|
| Advert (MongoDB) | < 15 мин | < 1 мин |
| Order / Payment | < 5 мин | ≈ 0 (idempotency, Payment Status Log) |
| Search (Elasticsearch) | < 30 мин | eventual (переиндексация) |
| Chat (Redis) | < 10 мин | best-effort |

Доступность 99,9 % допускает до ≈ 8,8 ч простоя в год.

## 6.2 Репликация и режимы работы

- **Сервисы без состояния** (шлюз, Read, Search, Chat и др.): ≥ 2 экземпляра, нагрузка делится балансировщиком; падение одного не останавливает систему.
- **Базы:** MongoDB Replica Set (1 primary + 2 secondary, авто-failover, большинство 2 из 3); Kafka RF = 3 (3 брокера); Elasticsearch ≥ 1 реплика шарда; кэш и pub/sub — отдельные Redis с Sentinel/Cluster.
- Узлы размещаются в разных зонах доступности одного региона, чтобы падение зоны затрагивало не больше одного узла.

## 6.3 Устойчивость к отказам

| Сбой | Реакция |
|---|---|
| Падение primary MongoDB | Авто-failover, запись недоступна на секунды |
| Падение Elasticsearch | Поиск деградирует, запись объявлений продолжается; индекс восстанавливается |
| Потеря Redis | Кэш: чтение идёт в MongoDB; чат: история из MongoDB |
| Недоступность Payment/Delivery Provider | timeout + retry + Circuit Breaker, idempotency-key |
| Сбой потребителя Kafka | Повторная обработка, DLQ, алерт по consumer lag |

## 6.4 Единые точки отказа (SPOF)

Шлюз и балансировщик — ≥ 2 экземпляра; брокер — 3 узла; БД — Replica Set. Оставшиеся риски: внешние провайдеры (смягчаются Circuit Breaker) и регион целиком (см. DR).

## 6.5 DR-план

- Один регион (ограничение ТЗ): между регионами Active-Active не реализуем, только бэкапы.
- Регулярные снапшоты MongoDB и Elasticsearch; версионирование S3 для фото.
- Payment Status Log — неизменяемый журнал для сверки после инцидента.
- Восстановление индекса Elasticsearch — полная переиндексация напрямую из MongoDB.
- При росте требований к SLA следующий шаг — warm standby во втором регионе (реплика MongoDB + минимальная инфраструктура); active-active между регионами не окупается (сложность консистентности платежей, примерно двукратная стоимость).
