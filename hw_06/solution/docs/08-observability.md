# 8. Observability

Стек: ELK (логи), Prometheus (метрики), Grafana (дашборды), сквозной слой для всех сервисов; трассировка — распределённый tracing.

## Ключевые метрики

| Метрика | Что показывает | Зачем |
|---|---|---|
| RPS и latency p50/p95/p99 по сервисам | Нагрузка и скорость | Требование ТЗ: поиск p99 < 200 мс |
| Error rate по эндпоинтам | Доля ошибок | Видно, какой метод ломается |
| Kafka consumer lag | Отставание Indexer/Moderation | Рост = устаревший поиск |
| ES query latency | Скорость Elasticsearch | Основа поиска |
| Cache hit-rate (Redis) | Доля попаданий в кэш | Падение → нагрузка на MongoDB |
| MongoDB replication lag | Отставание реплик | Влияет на RPO при failover |
| DLQ size | Необработанные сообщения | Каждое — потерянная операция |
| CPU / memory по подам | Загрузка | Когда масштабироваться |
| Uptime / SLA burn rate | Расход допустимого простоя | Контроль 99,9 % |
| Webhook delivery success rate | Успех вебхуков провайдера | Иначе статусы платежей не обновятся |

## Алерты

p99 поиска > 200 мс · error rate > 1 % · consumer lag выше порога · failover MongoDB · cache hit-rate < 80 % · всплеск отказов вебхуков · диск > 80 %.

> Пороги — типичные значения, уточняются по результатам нагрузочного теста и первых недель эксплуатации. Желательно добавить бизнес-метрики (созданные объявления и успешные заказы в минуту).
