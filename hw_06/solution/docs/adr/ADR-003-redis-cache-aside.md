# ADR-003: Redis cache-aside (LFU) для чтения объявлений

- **Статус:** Принято
- **Контекст:** 5 000 RPS пиковой нагрузки на чтение при 100 млн объявлений — прямое чтение из MongoDB на каждый запрос создаст неприемлемую нагрузку и латенси.
- **Решение:** Advert Read Service использует Redis как cache-aside слой с политикой вытеснения LFU (часто запрашиваемые объявления остаются в кэше дольше) и TTL; при промахе — чтение из MongoDB с последующей записью в кэш. Для защиты от cache stampede — request coalescing/distributed lock на "горячих" ключах.
- **Альтернативы:** Write-through кэш — отклонён: усложняет запись без выигрыша, так как write RPS низкий и не является узким местом; кэширование на уровне CDN/edge — отклонено для приватных/динамических данных объявления (актуальная цена, статус).
- **Последствия:** (+) резко снижена нагрузка на MongoDB на hot-path чтения; (−) возможна кратковременная отдача устаревших данных (допустимо по нефункциональным требованиям), нужен мониторинг hit-rate и защита от stampede.
